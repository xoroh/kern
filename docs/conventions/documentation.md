# Documentation rules

Status: current

We follow open standards instead of inventing our own. When a standard
evolves, we re-align — this file records what we follow and where it lands.

## Diátaxis mapping

| Quadrant | Home | Examples |
|---|---|---|
| Tutorials (learning) | `apps/site/` `/getting-started` | Install Kern, render a first `Button` |
| How-to (task) | `apps/site/` `/docs/guides` | Swap the theme, use Kern in React Native |
| Reference (information) | Generated from code + tokens: `docs/components.md`, `docs/platform-parity.md` | Component inventory, parity tables |
| Explanation (understanding) | `docs/adr/`, `docs/plan/`, skill canon | Why Base UI, why the renderer split |

Our addition on top: **skills as machine-readable reference**. Diátaxis
predates AI agents; `.agents/skills/kern/` carries the same knowledge in
agent-activatable form. Human and agent docs must agree — update both.

## Principles

1. One canonical source per fact. Docs explain and link — never compete.
2. Code/config is canonical for values; docs are canonical for meaning,
   ownership, boundaries, decisions.
3. Update docs in the same change as the code. Never defer.
4. Link, don't duplicate. Small clarifying examples are fine; mirrors aren't.
5. Smallest valid owner: package truth lives with the package, repo truth
   in `docs/`, product truth in `apps/site/`, agent truth in skills.
6. Voice follows the Google style guide: second person, present tense,
   sentence case, scannable headings.
7. **Generated files are never hand-edited.** `docs/components.md` comes
   from `bun run generate:components`. If it is stale, regenerate — do not
   patch it, and do not work around a generator bug by editing its output.

## Status labels

Every doc declares one, right after the title:

- `placeholder` — structure only, needs real content
- `draft` — written, not yet reviewed against implementation
- `current` — verified accurate
- `stale` — suspected out of date (fix or re-verify)
- `deprecated` — phased out, kept as reference

`current` is a claim, not a default. Before marking a page `current`,
re-read the code it describes and confirm every path, name, and command in
it still exists.

## Merge gate

Before merge: behavior docs updated, changeset added for `packages/`
changes (see [`changesets.md`](changesets.md)), skill refs updated if
guidance changed, `Status:` lines correct, `bun run lint` clean, README
indexes list new files. No empty placeholders, no unrelated edits, no pasted
source values.

Docs-only changes to `docs/`, `.agents/`, or root markdown need no changeset
and no test run — but they do need the links checked:

```bash
# every relative link in docs/ and .agents/ resolves
grep -rhoE '\]\(([^)#]+)' docs .agents README.md CONTRIBUTING.md \
  | sed -E 's/^\]\(//' | sort -u
```
